# 首页改版与 Era 博物馆设计

## 背景

当前首页由 `今日推荐`、`最近动态` 和两个快捷入口组成。问题不在于模块数量少，而在于首页缺少明确的价值中心：

- `今日推荐` 信息密度低，吸引力不足
- `最近动态` 有更新感，但不足以支撑首页的独特体验
- 用户打开首页后，无法立刻感知这是一个有明确世界观的 Taylor Swift 粉丝产品

产品目标调整为：

- 首页既要承接未来 API 化后的动态信息
- 也要建立属于产品自己的沉浸感和辨识度
- MVP 阶段优先做最核心、价值最清晰的模块，不追求信息堆叠

## 设计结论

首页采用 `动态头部 + Era 横滑卡片 + 新闻摘要` 的混合骨架。

核心判断：

- 有重大事件时，首页优先展示事件信息
- 无重大事件时，首页由 Era 内容承担主叙事
- Era 博物馆不是单独的二级入口概念，而是首页主体验的一部分

因此，首页不再保留 `今日推荐`，也暂不引入 `今日焦点`、`随机发现` 等价值尚不清晰的增强模块。

## 首页信息架构

### 1. 动态头部 Hero

顶部 Hero 用于承接最值得被优先关注的事件。

展示规则：

- 当存在即将发布的新专、Taylor's Version、巡演开始、巡演倒计时等重大事件时，显示 Hero
- 当没有足够强的事件时，Hero 可隐藏或降级为较小提示位

设计目的：

- 承担首页的 `追更价值`
- 为未来 API 化预留最自然的动态入口
- 保证首页在重大节点时具备明确的“现在该看什么”指向

### 2. Era 横滑卡片

首页中部直接展示多个 Era 卡片，作为首页的核心视觉和主互动区。

表现形式：

- 横向滑动浏览多个 Era
- 每张卡片代表一个 Era 展厅入口
- 用户可从首页直接感知不同 Era 的气质差异

该区域的定位不是“资料馆入口导航”，而是首页本身先展开一层 Taylor 世界。

### 3. 新闻摘要

新闻模块保留，但降级为辅助信息区。

展示规则：

- 保留 2 到 3 条轻量摘要
- 以“维持更新感”为主，不承担首页主叙事
- 避免在视觉上压过动态 Hero 和 Era 卡片区

## Era 卡片内容模型

MVP 第一版中，每张 Era 卡片只承载最必要的信息，避免首页承载过多细节。

建议字段：

- `id`
- `name`
- `cover`
- `themeColor` 或视觉主色
- `tagline`
- `target` 或对应跳转目标

字段说明：

- `name`：Era 名称
- `cover`：视觉封面图
- `themeColor`：用于建立不同 Era 的氛围区分
- `tagline`：一句话导语，帮助用户快速理解该 Era 的气质
- `target`：点击后进入对应 Era 的展厅页或专题页

第一版不在首页卡片中强行加入以下内容：

- 代表展品列表
- 标志事件列表
- 统计数字
- 复杂标签组合

这些内容可以在后续迭代中放入 Era 详情页或下一版首页增强中。

## “Taylor 博物馆” 的 MVP 定义

“Taylor 博物馆” 在 MVP 阶段不等于一个庞大的虚拟展览系统，而是一个清晰的内容组织方向：

- 以 Era 为一级组织单位
- 每个 Era 是一个可进入的展厅
- 首页先通过横滑卡片展示 Era
- 用户进入某个 Era 后，再看到更完整的展厅内容

第一版首页只负责把用户带到正确的 Era 氛围中，不在首页承担完整展厅叙事。

这意味着博物馆概念在 MVP 里是 `结构上的核心`，不是 `功能上的重系统`。

## MVP 明确不做的内容

为保持首页聚焦，第一版明确不做：

- `今日推荐`
- `今日焦点`
- `随机发现`
- 首页内展开式 Era 详情
- 复杂筛选、排序、多态切换
- 过重的编辑策展逻辑

这些模块的问题不是创意不足，而是当前阶段缺少稳定的价值锚点，容易让首页重新变成信息拼盘。

## 数据与接口设计建议

虽然当前项目基于本地 mock，但首页设计应直接面向未来 API 替换。

建议首页统一收敛为一个聚合数据结构：

- `spotlight`
- `eras`
- `news`

推荐语义：

- `spotlight`：顶部事件位，允许为空
- `eras`：首页横滑卡片数组
- `news`：新闻摘要列表

在 mock 阶段：

- 页面继续通过 selector 获取聚合数据
- 可新增首页专用 selector，避免页面层自己拼数据

在 API 阶段：

- 建议新增首页聚合接口，例如 `GET /home`
- 接口一次性返回 `spotlight + eras + news`
- 页面层逻辑保持不变，仅替换数据来源

这种方式可以避免未来接 API 时把页面重写成多个独立请求拼装页。

## 页面行为建议

首页的行为目标应保持简单直接：

- 用户进入首页，优先看到是否有重大事件
- 用户可以立即横滑浏览 Era
- 用户点击 Era 卡片进入对应展厅页或专题页
- 用户向下可继续查看轻量新闻摘要

首页不承担深度浏览任务，而是承担“建立兴趣并完成导流”的任务。

## 演进路线

推荐迭代顺序：

1. 完成首页 `动态 Hero + Era 横滑卡片 + 新闻摘要`
2. 落地 Era 详情页 / 展厅页
3. 增强 Era 卡片的视觉和信息密度
4. 再评估是否引入策展型增强模块，例如本期展品、随机发现或主题焦点

这样可以确保每一步都建立在已有清晰价值之上，而不是提前堆功能。

## 风险与约束

### 风险 1：Era 卡片做成“专辑列表换皮”

如果只有封面和名字，用户会把它理解为普通专辑入口，而不是展厅入口。

应对方式：

- 为 Era 卡片补充一句明确的气质导语
- 使用视觉主色或风格差异强化 Era 感
- 后续在目标页中延续“展厅”语义，而不是回到普通列表页

### 风险 2：动态 Hero 与新闻模块重复

如果 Hero 和新闻都展示相似内容，会造成首页叙事重叠。

应对方式：

- Hero 只承接“最重要的一件事”
- 新闻只保留摘要和列表属性
- 不让新闻承担顶部主视觉

### 风险 3：首页模块重新变重

一旦把焦点、发现、推荐等模块继续加回首页，信息架构容易再次失焦。

应对方式：

- MVP 阶段坚持三段式结构
- 任何新增模块都必须先明确价值锚点，再决定是否进入首页

## 实施建议

实现时建议优先新增首页聚合 selector，并让页面只消费聚合结果，而不是自行读取各类原始数据。

建议后续实现分为两步：

1. 先完成首页骨架替换与 Era 卡片交互
2. 再补 Era 数据模型和后续展厅页承接

这样可以保证首页先获得清晰的产品表达，再逐步补齐内容深度。
