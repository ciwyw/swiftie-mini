# 曲库模块重构设计

## 1. 目标

本设计用于重构当前 Taylor Swift 粉丝向微信小程序中的曲库模块，使其从“首页直接堆叠专辑与歌曲列表”的内容页，调整为“入口优先的内容中枢”。

本次重构的核心目标如下：

- 曲库 Tab 首页只保留核心内容入口，不再直接展示完整歌曲列表
- 收藏歌曲从个人页完整列表调整为独立页面入口
- 为非巡演语境的内容建立独立体系，包括 `Live 表演` 与 `纪录片`
- 将 `MV` 作为歌曲附属资产融入专辑列表、歌曲列表与歌曲详情页，而不是独立一级频道
- 增加 `分类合集` 能力，支持两层结构：
  - `歌曲情绪 / 场景分类`
  - `混合型专题合集`
- 在信息架构和数据模型上，明确区分“曲库内容视频”和“巡演模块视频”

本次设计继续沿用以下约束：

- 微信小程序原生开发
- TypeScript + WXML + WXSS
- 全部使用本地 mock 数据
- 不依赖真实后端
- 非 Tab 页面跳转统一使用 `wx.navigateTo`
- Tab 切换统一使用 `wx.switchTab`
- 不使用第三方 UI 组件库
- 视觉方向保持简洁白底和卡片布局
- 当前会话中用户明确要求：不要做任何 git 操作

## 2. 总体信息架构

### 2.1 曲库首页定位

`pages/library/index` 从“内容列表页”改为“内容入口页”。

首页不再承担以下职责：

- 展示完整歌曲列表
- 展示完整收藏列表
- 承担推荐流或瀑布式内容发现

首页只负责组织和解释内容入口，让用户快速进入目标频道。

### 2.2 曲库首页一级入口

重构后的曲库首页保留以下 6 个一级入口：

- `专辑`
- `歌曲`
- `Live 表演`
- `纪录片`
- `分类合集`
- `我的收藏`

每个入口应以卡片形式展示，并包含：

- 标题
- 一句简短说明
- 可选的轻量数量信息或更新信息

边界约束：

- 首页第一期不引入推荐流
- 首页不混入任何巡演模块视频
- 首页不单独设置 `MV` 一级入口

### 2.3 MV 的频道定位

`MV` 不作为独立一级频道，也不提供完整独立列表页。

原因如下：

- 用户查找 MV 的主路径通常是先找到歌曲，再查看该歌曲是否有 MV
- MV 与歌曲关系强绑定，适合作为歌曲的附属资产而不是平行内容频道
- 若将 MV 独立为一级入口，会使曲库首页入口过多，削弱信息聚焦

因此本次设计中：

- MV 作为歌曲的视频资产存在
- MV 主要出现在专辑歌曲列表、歌曲列表和歌曲详情页中
- 后续如需在 `分类合集` 中收录 MV，可复用同一套数据资产，但不改变其主浏览路径

## 3. 页面结构调整

### 3.1 曲库首页 `pages/library/index`

重构后页面只保留入口卡片，不再平铺完整歌曲列表。

页面采用以下布局：

- 顶部页面标题与简短说明
- 一级入口卡片区
- 可选的轻量“最近更新”占位区

第一期可不实现“最近更新”，优先保持页面简洁。

### 3.2 专辑列表 `pages/album/index`

现有专辑页面可继续承担专辑浏览职责，但需要补充与歌曲资产相关的延展信息。

页面需要增强如下：

- 专辑歌曲列表中，为存在 MV 的歌曲增加 `MV` 标签
- 点击歌曲仍进入歌曲详情页

若当前 `pages/album/index` 已同时承担“专辑列表 + 单专辑详情”职责，则本次实现可延续当前结构，不要求额外拆页；但在交互上应确保用户能从曲库首页稳定进入完整专辑浏览路径。

### 3.3 歌曲列表页

需要新增独立歌曲列表页，用于承接曲库首页中的 `歌曲` 入口。

页面职责：

- 展示完整歌曲列表
- 保持轻量、可快速浏览
- 为存在 MV 的歌曲展示 `MV` 标签
- 点击进入歌曲详情页

第一期不加入复杂筛选，但数据结构必须预留按专辑、情绪、是否有 MV 筛选的扩展空间。

### 3.4 歌曲详情页 `pages/song/index`

歌曲详情页继续以歌曲信息、歌词、收藏为核心。

新增一个 `视频内容` 模块，用于展示该歌曲的附属内容资产。

展示规则：

- 若歌曲存在 MV，则优先展示 MV 卡片或观看入口
- 若歌曲有关联的代表性非巡演 `Live 表演`，可在同一区块追加 1 至 2 条相关内容入口
- 若歌曲没有任何视频资产，则整个模块隐藏

该页面仍然保持“以歌曲为中心”的信息顺序，不应被视频内容喧宾夺主。

### 3.5 Live 表演列表页

需要新增独立 `Live 表演` 列表页，用于承接非巡演语境的表演内容。

该页面只收录以下类型内容：

- 典礼表演
- 音乐节表演
- 电台或品牌活动表演
- 电视节目表演
- 特别舞台或串烧

典型来源包括但不限于：

- 格莱美
- AMA
- iHeartRadio
- SNL
- BBC
- Tiny Desk

该页面不收录以下内容：

- 巡演单场饭拍
- 场次 recap
- 排队 vlog
- 巡演现场上传视频

### 3.6 纪录片列表页

需要新增独立 `纪录片` 列表页，用于承接长内容。

该页面收录的内容包括：

- 正片纪录片
- 演唱会电影
- 幕后特辑
- 录音室花絮
- 平台特别节目

页面以卡片浏览为主，每条内容至少展示：

- 标题
- 年份
- 类型标签
- 一句简介

### 3.7 分类合集页

需要新增独立 `分类合集` 页面，并采用两层结构：

第一层为 `歌曲情绪 / 场景分类`，例如：

- 抒情
- emo
- 欢快
- 治愈
- 深夜循环
- 演唱会大合唱

第二层为 `混合型专题合集`，例如：

- 领奖台名场面
- 电影感叙事作品
- 失恋时期循环内容
- 成长线内容回顾

合集详情页的内容项允许混合出现：

- `Song`
- `Song MV`
- `Performance`
- `Documentary`

但每个内容项必须以类型标签明确区分，避免用户混淆。

### 3.8 收藏列表页

需要新增独立 `收藏` 页面，用于承接用户收藏歌曲列表。

个人页不再直接平铺完整收藏列表，而是调整为：

- 收藏入口
- 收藏数量或轻量概览

这样可以避免个人页内容过长，并与曲库首页的“我的收藏”入口形成一致路径。

## 4. 内容分类与模型边界

### 4.1 Song

`Song` 仍然是曲库中的基础实体。

在当前结构基础上，需要扩展与视频资产相关的附属字段，使其能表达：

- 是否存在 MV
- MV 标题
- MV 封面
- MV 跳转信息或外链占位

设计原则：

- MV 从属于歌曲
- 歌曲详情页是查看 MV 的主页面
- 歌曲列表和专辑歌曲列表只负责提示“该歌曲可观看 MV”

### 4.2 Performance

新增 `Performance` 作为独立内容类型，用于承载非巡演 live 表演。

该类型的字段应围绕“活动 / 节目 / 舞台”组织，至少包括：

- `id`
- `title`
- `songIds`
- `eventName`
- `year`
- `cover`
- `source`
- `duration`
- `summary`

设计原则：

- `Performance` 属于曲库内容
- `Performance` 不参与巡演模块的数据流
- 一条 `Performance` 可关联一首或多首歌曲

### 4.3 Documentary

新增 `Documentary` 作为独立内容类型，用于承接长内容。

字段至少包括：

- `id`
- `title`
- `year`
- `category`
- `cover`
- `platform`
- `duration`
- `summary`
- `relatedSongIds`

设计原则：

- `Documentary` 可以与歌曲存在关联，但不要求强绑定
- `Documentary` 的主浏览路径应独立于歌曲频道

### 4.4 Collection

新增 `Collection` 作为内容组织实体。

字段至少包括：

- `id`
- `title`
- `type`
- `description`
- `cover`
- `items`

其中 `type` 至少支持：

- `mood`
- `scenario`
- `editorial`

其中 `items` 允许收录多种内容类型：

- `song`
- `mv`
- `performance`
- `documentary`

设计原则：

- `Collection` 只负责组织内容，不替代内容本体
- 同一内容可以被多个合集复用
- 合集既可以偏歌曲分类，也可以偏混合专题

## 5. 曲库与巡演模块的隔离规则

### 5.1 巡演视频的归属

当前巡演模块中的视频数据，继续只服务以下上下文：

- 场次详情页
- 巡演现场回顾
- 饭拍与排队 vlog

这些视频的本质是 `Show` 语境下的上传内容，不应进入曲库内容体系。

### 5.2 曲库视频的归属

曲库中的视频资产只包括：

- 歌曲附属的 `MV`
- 非巡演的 `Live 表演`
- 纪录片与长内容

因此需要明确以下边界：

- 巡演饭拍不是 `Live 表演`
- 巡演场次视频不是 `MV`
- 曲库 `Live 表演` 不是 `Show Video`
- 曲库 `纪录片` 不从巡演模块复用

### 5.3 选择器与数据目录边界

当前 `data/videos.ts` 与 `utils/selectors.ts` 主要服务巡演模块。

本次设计要求将曲库相关新增数据拆分为独立 mock 文件，而不是继续往巡演视频数据中叠加字段。

新增的 mock 数据文件包括：

- `data/performances.ts`
- `data/documentaries.ts`
- `data/collections.ts`

若 MV 结构较轻，可直接挂在歌曲数据中；若后续 MV 元数据明显增长，可再单独拆分 `data/songVideos.ts`。

对应地，选择器也应拆分出曲库内容读取函数，避免出现“一个 videos 选择器同时服务巡演和曲库”的混乱结构。

## 6. 页面交互规则

### 6.1 曲库首页

- 一级入口卡片整体可点击
- 入口跳转均使用 `wx.navigateTo`
- 首页不出现长列表滚动

### 6.2 歌曲列表和专辑歌曲列表

- 歌曲项点击进入歌曲详情页
- 存在 MV 的歌曲展示 `MV` 标签
- 第一期开关项不超过一个轻量标签，避免视觉噪音

### 6.3 歌曲详情页

- 保留现有收藏交互
- 保留歌词逐句展示
- 新增 `视频内容` 模块
- 无 MV 且无相关表演时整块隐藏

### 6.4 Live 表演页

- 单个表演卡片点击进入对应详情或外链占位页
- 第一阶段可先做列表页与详情占位，不要求一开始支持复杂播放页

### 6.5 纪录片页

- 单个纪录片卡片点击进入详情或观看信息页
- 第一阶段重点是内容浏览与归档，不强制要求视频在线播放能力

### 6.6 合集页

- 合集列表先展示分类块，再展示具体合集
- 点击合集进入内容集合详情
- 混合内容列表必须显示类型标签，避免歌曲、MV、现场和纪录片混淆

### 6.7 收藏页与个人页

- 个人页仅保留收藏入口和轻量概览
- 收藏完整列表迁移到独立页面
- 收藏项仍然点击进入歌曲详情页

## 7. 分阶段范围建议

### 7.1 本次重构必须覆盖

- 曲库首页改为入口页
- 歌曲列表改为独立页面
- 收藏列表改为独立页面
- 歌曲详情新增 MV 入口模块
- 新增 `Live 表演` 列表页
- 新增 `纪录片` 列表页
- 新增 `分类合集` 列表页
- 明确新增 mock 数据与 selector 边界

### 7.2 本次重构不强制覆盖

- 推荐流
- 排序与复杂筛选
- 真正的视频播放能力
- 评论、发帖、关注等重社区能力
- 用户自建合集

这些能力可以在后续迭代中逐步补齐，不应影响本次曲库重构的完成度。

## 8. 测试与验证关注点

本次设计落地后，至少需要验证以下行为：

- 曲库首页不再出现完整歌曲列表
- 曲库首页所有入口都能正确跳转
- 歌曲列表能完整展示所有歌曲
- 收藏列表从个人页迁移后，收藏数据仍能正常读取
- 有 MV 的歌曲在列表中能正确显示标签
- 歌曲详情页在有 MV 时展示视频模块，无 MV 时正确隐藏
- `Live 表演` 页面不混入任何巡演饭拍视频
- `纪录片` 页面能正确展示独立长内容
- `分类合集` 能正确区分 `song / mv / performance / documentary`
- 巡演模块的 `data/videos.ts` 与曲库新增内容数据不存在混用

## 9. 设计结论

本次曲库重构的最终方向是：

- 首页做中枢，不做列表堆叠
- 歌曲仍然是核心内容实体
- MV 归属歌曲，不做独立一级频道
- 非巡演 `Live 表演` 与 `纪录片` 作为独立内容频道建立
- `分类合集` 承担社区气质与内容发现，但不演变成推荐流
- 巡演视频与曲库视频在数据和页面边界上彻底分离

该设计既满足当前 MVP 对内容完整性的要求，也为后续扩展 `主题运营`、`内容沉淀`、`更强的个人偏好体验` 预留了明确结构。
